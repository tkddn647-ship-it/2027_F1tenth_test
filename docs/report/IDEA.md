# 아이디어: depth 카메라 + 초파리 커넥톰으로 맵 없이 달리기

F1TENTH / Roboracer 2026 · 아주대

## 1. 한 줄

**LiDAR·맵·위치추정 없이, depth 카메라 한 대가 본 것을 초파리 시각 회로에 넣어 바로 조향·속도를 낸다.**
회로는 시뮬에서 강화학습(SAC)으로 학습하고, 실차 Jetson 에서는 torch 없이 그대로 돌린다.

## 2. 왜 초파리 커넥톰인가

| 이유 | 내용 |
|--|--|
| 하는 일이 같다 | 초파리 시각계는 **빠르게 날면서 벽·장애물을 피하고 코스를 유지**하도록 진화했다. 좌우 흐름 균형으로 가운데 유지(HS), 다가오는 물체 감지(LPLC2) 같은 회로가 이미 있다 — 레이싱에 필요한 것과 같다 |
| 작고 빠르다 | 학습되는 값이 약 760개 (LiDAR 쪽 CNN 정책은 10만 개 이상). Jetson CPU 에서 프레임당 수 ms, GPU 불필요 |
| 시뮬→실차에 유리할 것으로 기대 | 연결 구조는 초파리 시각엽의 알려진 세포 유형·연결 방식을 본떠 **고정**하고(실제 연결 데이터는 아님, 나중에 flyvis 로 교체 후보) 연결 세기만 학습 → 시뮬의 사소한 특징에 덜 맞춰질 것으로 기대 (검증 필요) |
| 들여다볼 수 있다 | "어느 뉴런이 왜 켜져서 왼쪽으로 꺾었나"를 볼 수 있다 (아래 그림의 시각엽·DN 막대) |
| 새로움 | 대회에서 보기 드문 접근 — 연구·발표 가치 |

## 3. 어떻게

```
Gemini 2L depth (30 fps, 카메라 칩이 계산)
  → 파리 눈 격자 16×64 '가까움' 영상 (바닥 제거, 정면·지평선에 칸을 몰아줌)  × 최근 3프레임
  → 초파리 시각엽 회로: 움직임 검출(T4/T5) → 좌우·상하 흐름(HS/VS), 다가옴(LPLC2), 가장자리(LC), 가까움(L3)
  → 하행 뉴런 48개 → 조향·속도
```

- **왜 depth:** 덕트·장애물 색이 랜덤이어도 거리만 재므로 영향이 없다. RGB 는 색·조명 변화를 다 학습해야 해서 작은 회로에 맞지 않는다.
- **학습:** 시뮬(LiDAR 로 만든 트랙 맵의 벽을 33 cm 덕트로 세움)에서 SAC. 학습 때만 레이싱라인을 보는 critic 을 써서 빠른 라인을 배우게 하고,
  실차에 올라가는 회로는 카메라·속도·IMU 만 본다.
- **실차:** 카메라가 오면 실제 덕트를 찍어 시뮬 센서(오차·구멍·지연)를 맞춘 뒤 재학습 → 저속(2 m/s)부터.
- **고속 주의:** 30 fps 자체보다 브레이크 없음(타력 감속 ~11 m vs depth 7 m)과 빠른 옆 움직임 검출이 문제 → 브레이크·검출기 보강 필요.
