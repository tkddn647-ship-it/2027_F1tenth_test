## 2. 방향

| 항목 | 결정 |
|--|--|
| 센서 | Orbbec Gemini 2L **depth 만** (RGB·LiDAR 안 씀) |
| 정책 | **초파리 커넥톰 회로만** (CNN·MLP 없음) |
| 입력 | 과거 3프레임, **30 Hz** (Gemini 2L depth 최대 30 fps) |
| 왜 depth | 덕트·장애물 색이 랜덤이어도 거리만 재므로 영향 없음. RGB 는 색·조명 랜덤화가 크게 필요 |
| 맵 | LiDAR 로 만든 맵 그대로. 실제 카메라로 맞출 것은 **센서 모델**(오차·구멍·지연) |
| Jetson 부하 | depth 는 카메라가 계산, Jetson 은 프레임당 약 2.5 ms |

## 3. 앞으로 할 일

**카메라 오기 전 (시뮬)**
1. torch 테스트 통과 확인 → 짧은 학습 → 본 학습 → ifac·팀 맵 평가 (LiDAR v3 와 비교)
2. 센서를 일부러 나쁘게 해서 평가 (잡음·구멍·각도·지연)
3. 개선: 덕트가 잘 보이도록 행 배치 조정, 빠른 움직임용 검출기 추가

**카메라 도착 후**
1. 실제 덕트를 거리별로 찍어 오차·구멍 측정 (특히 은박·검정 재질 구멍)
2. LiDAR 와 같이 달고 수동 주행 녹화 → 시뮬 센서 모델 보정 → 재학습
3. 실차 2.0 m/s 부터

## 4. 고속(7 m/s) 메모

30 fps 자체는 큰 문제가 아니다 (LiDAR 40 Hz 대비 반응 4 ms 차이). 고속에서 문제는
**브레이크 없음**(타력 감속에 ~11 m 필요, depth 는 7 m 까지 봄), **빠른 옆 움직임 검출**, **먼 거리 depth 품질**.
→ 고속 전에 카메라 지연 실측, 브레이크 가능 여부 확인 필요. 지금 정책 범위는 2~5 m/s.
