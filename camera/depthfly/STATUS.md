# depthfly 현재 상태 정리 (2026-10-04)

depth 카메라(Orbbec Gemini 2L) 한 대와 초파리 커넥톰 회로만으로 달리는 강화학습 정책.
이 문서는 **지금 코드가 실제로 어떻게 되어 있는지**(층별)와 **학습 결과가 어디까지 왔는지**를 한 곳에 모은 것이다.
"실측"은 이 PC 시뮬에서 직접 돌려 얻은 숫자, "추정"은 실물로 재지 않은 값이다. 실차·실제 카메라로 잰 값은 아직 하나도 없다.

## 1. 한눈에

| 항목 | 상태 |
|--|--|
| 장애물 없는 주행 | **된다.** 최고 모델이 16 / 16 완주, 팀 맵 랩 10.6~11.3 s (실측) |
| 장애물 2개 주행 | **안 된다.** 60번 중 32번 충돌 (실측) |
| 원인 (추정) | 시야 91° + 기억 0.1 s → 장애물이 옆으로 오면 안 보이고, 방금 본 것도 잊는다 |
| 지금 도는 학습 | 없음 |
| 쓸 수 있는 최고 모델 | `runs/depthfly_v3c/best_model.zip` (30만 스텝, 브레이크 없음, 2~8 m/s) |
| 결정 대기 | 장애물 회피가 필요한가 / "과거 3프레임" 조건을 풀어 짧은 기억을 넣어도 되는가 |
| 아직 안 한 것 | 실제 카메라로 센서 모델 보정, ROS2 노드 C++ 포팅, 실차 시험 |

비교 기준: 레이싱라인 pure pursuit ifac 14.1 s, LiDAR 정책(mapless40 v3) ifac 10.9 s / 팀 맵 9.63 s.

## 2. 전체 흐름

```
Gemini 2L depth 영상 (30 fps)
  → [1] 눈: 16×64 '가까움' 영상            (sensor.py)
  → [2] 기억: 최근 3프레임 + 차량 상태 14   (env.py, camfly/env.py CamHistory)
  → [3] lamina: 프레임 사이 변화 ON/OFF     (brain.py)
  → [4] T4/T5: 4방향 움직임
  → [5] 시각엽 출력 96개 (HS·VS·LPLC2·LC·L3)
  → [6] 하행 뉴런 DN 48개
  → [7] 선형 읽기 → 조향, 속도              (policy.py)
  → /drive
학습할 때만: critic 이 같은 회로 + 레이싱라인·장애물 정보 27개를 본다 (실차에는 없음)
```

## 3. 층별 구성

### [1] 눈 — depth 를 16×64 가까움 영상으로

| 항목 | 값 | 출처 |
|--|--|--|
| 시야 | 가로 91° × 세로 66° | 데이터시트 |
| 장착 | 높이 0.18 m, 아래로 10°, 무게중심 앞 0.139 m | **가정** |
| 열 64개 | 정면 ±15° 에 절반(32열, 간격 약 0.9°), 나머지는 바깥 | 설계 |
| 행 16개 | 지평선 ±8° 에 12행(간격 1.45°), 위아래 ±15.5°, ±23° 에 2행씩 | 설계 (v2) |
| 값 | 가까움 = 0.25 m ÷ 수평거리. 0.25 m 에서 1, 1 m 에서 0.25, 7 m 에서 0.036 | 설계 |
| 측정 없음 = 0 | 7 m 밖, 0.25 m 안쪽, depth 구멍, 하늘 | 0.25 m·7 m 는 데이터시트 |
| 높이 판정 | 높이가 5 cm + d·tan1.5° 이상, 0.40 m + d·tan1.5° 이하인 점만 남김 (바닥·배경 제거) | 설계 |
| 구멍 메우기 | 값이 없는 칸은 직전 값을 최대 2프레임 유지 | 설계 |
| 실차 칸 값 | 칸 주변 7×7 픽셀 중 유효한 것의 중앙값 | 설계 |

시뮬에서 넣는 오차:

| 항목 | 값 | 출처 |
|--|--|--|
| 거리 오차 | σ = 0.01·d² (2 m 에서 4 cm, 4 m 에서 16 cm) | 데이터시트 상한 (≤ 2 % @ 2 m) |
| 구멍 확률 | 2 % + 15 %·(d/7)², 칸마다 독립 | **추정** |
| 장착 pitch 오차 | 에피소드마다 ±1°, 프레임마다 σ 0.3° | **추정** |
| 지연 | 30 ms | **추정** (데이터시트에 없음) |
| 트랙 | LiDAR 2D 맵의 벽을 높이 33 cm 덕트로 세움 | 맵 = LiDAR 실측, 높이 = 규정 |
| 장애물 | 원통 반지름 0.12~0.30 m, 높이 0.30 m | 가정 |
| 없음 | 덕트 사이 틈, 가장자리 가짜 점, 반사 재질의 큰 구멍, 햇빛, 진동 | — |

실측: 주행 중 값이 25 % 넘게 있는 행은 16행 중 4행. 평평한 바닥만 있을 때 pitch 오차 ±1.5° 까지 가짜 칸 0.

### [2] 기억 — 관측

| 이름 | 크기 | 내용 |
|--|--|--|
| `near` | 3 × 16 × 64 | 가까움 영상 n−2, n−1, n (0.1 초 분량) |
| `state` | 14 | 평균 속도 ×3, 평균 요레이트 ×3, 최신 요레이트, 직전 명령 (조향·속도) ×2, 프레임 간격 ×3 |
| `priv` | 27 | 레이싱라인 오차·곡률·기준 속도, 앞 장애물. **critic 전용, 실차에 없음** |

이 0.1 초가 정책이 가진 기억의 전부다. 순환 구조나 누적 상태는 없다.

### [3] lamina — 변화 검출

- 빠른 갈래 = 프레임 n − (n−1), 느린 갈래 = (n−1) − (n−2).
- 대비 적응: Δ → Δ ÷ (|Δ| + 0.01). 주행 중 가까움 변화가 평균 0.003 으로 작아서, 이게 없으면 움직임 신호가 가까움의 1/3000 이었다 (실측).
- ON = 가까워짐(+), OFF = 멀어짐(−) 으로 나눔.
- L3 경로 = 현재 가까움을 그대로 전달.

### [4] T4 / T5 — 방향별 움직임

- Reichardt 상관기: 느린 갈래 × 옆 칸의 빠른 갈래 − 그 반대. 왼·오·위·아래 4방향.
- T4 는 ON, T5 는 OFF 를 담당. 방향별 이득 8개를 학습.
- 이웃한 **한 칸** 사이의 움직임만 잰다. 옆 벽은 2 m/s 에서도 프레임당 2칸을 넘어가 방향을 잘못 읽을 수 있다 (계산, 실험 아님).

### [5] 시각엽 출력 96개

시야를 가로 8섹터(섹터당 8열, 0~3 = 오른쪽, 4~7 = 왼쪽) × 세로 2밴드(위 8행, 아래 8행)로 나눠 평균한다.

| 경로 | 개수 | 뜻 | 고정 이득 |
|--|--|--|--|
| HS | 16 | 좌우 흐름 (왼쪽 − 오른쪽) | 15 |
| VS | 16 | 상하 흐름 | 15 |
| LPLC2 | 8 | 다가옴 = 가까움 증가율 Δn/n, 섹터별 (문턱 0.005) | 7 |
| LC | 32 | 가장자리 (가로 16 + 세로 16) | 10 |
| L3 평균 | 16 | 섹터·밴드별 평균 가까움 | 1 |
| L3 최대 | 8 | 섹터별 가장 가까운 값 | 1 |

고정 이득은 경로별 평균 크기를 0.03~0.1 로 맞추려고 정한 설계값이다. 그 위에 학습되는 이득 5개(1 에서 시작)가 곱해진다.
실측: 움직임 경로(HS·VS·LPLC2)는 주행 중 크기가 잡음만 있을 때의 약 3배.

### [6] 하행 뉴런 DN 48개

- 왼쪽 20 + 오른쪽 20 + 가운데 8.
- 각 DN 은 위 96개 중 12개만 받는다 (**배선 고정**). 학습되는 건 연결 세기와 바이어스뿐이고, 부호는 못 바꾼다.
- 부호 규칙: 같은 쪽 시야는 흥분(+), 반대쪽은 억제(−). 오른쪽 DN 은 왼쪽 DN 의 거울상. 가운데 DN 은 가까움·다가옴에 억제, 바깥쪽 흐름에 흥분.
- 출력 = tanh(Σ 부호 × 세기 × 입력 + 바이어스), 범위 −1~+1.
- 이 배선은 **실제 초파리 연결 데이터가 아니라** 위 원칙으로 만든 합성 배선이다.
- 관찰 (실측, 충돌 장면 1건): 벽에 바짝 붙으면 왼쪽 묶음이 거의 전부 +1, 오른쪽이 거의 전부 −1 로 포화된다.

### [7] 읽기 — 행동

- [DN 48 ‖ state 14] = 62개 → **선형 한 층** → tanh → (조향, 속도). 은닉층 없음.
- 조향 ±21.4°, 속도 2~8 m/s (실차 최고 7 m/s, 8 은 여유분). 최저 속도 2 m/s 아래로는 못 내려간다.
- 학습되는 값: actor 전체 4,921개. 그중 실제로 쓰이는 건 DN 세기 576 (48×12) + 바이어스 48 + 이득 13 + 읽기 126 ≈ 760개.

### critic (학습 전용)

- 같은 회로의 별도 사본 + state 14 + priv 27 + 행동 2 → MLP 256·256 → Q 값. 2개 + 타깃 2개.
- 레이싱라인은 여기에만 들어간다. 배포되는 actor 는 레이싱라인을 모른다.

## 5. 학습 방법

1. **모방학습 (DAgger)**: 맵을 아는 선생님 운전자를 흉내 내어 회로를 초기화. 14회 반복 × 1.5만 스텝.
2. **SAC 강화학습**: 그 초기값에서 시작. 처음 3만 스텝은 critic 만 학습.

| 설정 | 값 |
|--|--|
| 맵 | ifac 3, roboracer_0817 3, Spielberg 1, Silverstone 1, Monza 1 (가중치) |
| 환경 수 / 배치 / 버퍼 | 4 / 256 / 15만 |
| 학습률 / γ | 3e-4 / 0.9967 (0.1 초당 0.99) |
| 탐색 | 목표 엔트로피 −3.5, 행동 잡음 σ 약 0.1. 실제 엔트로피 계수는 약 0.0014 까지 내려감 (실측) |
| 평가 | 5만 스텝마다 고정 6장면 (맵 2 × 출발 3, 그중 4장면은 장애물 2개) |
| 속도 | 이 PC(CPU, GPU 없음)에서 10만 스텝에 약 67분 (실측) |

## 6. 학습 이력과 결과

| 이름 | 무엇을 바꿨나 | 스텝 | 결과 |
|--|--|--|--|
| v3b | 레이싱라인 선생님 모방 → SAC | 60만에서 중지 | 최고 25만 스텝. 넓은 평가: 장애물 없음 12 / 16, 장애물 2개 5 / 16 완주 |
| **v3c** | v3b 최고 + 라인 밖 출발 | 25만 → 75만 | **최고 30만 스텝.** 장애물 없음 16 / 16, 장애물 2개 10 / 16 완주. 팀 맵 랩 10.6~11.3 s |
| v3d | v3c 최고 + 브레이크 | 30만 → 70만 | 효과 없음 (아래 표) |
| bc4 | 장애물을 피하는 선생님으로 모방학습 다시 | 21만 (모방만) | 더 나쁨 (아래 표). 강화학습은 시작 안 함 |

**장애물 2개, 30초 주행 60번 (맵 2개 × 30, 실측)**

| 운전자 | 충돌 |
|--|--|
| 레이싱라인 pure pursuit (v3b·v3c 의 선생님) | 53 / 60, 전부 장애물 정면 |
| 장애물을 피하는 선생님 (`expert.py`) | 6 / 60 |
| v3c 최고 모델 | 32 / 60 (장애물 정면 약 12, 벽 약 20) |
| v3c 최고 모델에 브레이크만 켬 | 32 / 60 |
| v3d 최종 (브레이크로 학습) | 33 / 60 |
| 피하는 선생님을 모방한 정책 | 36~43 / 60 |

읽는 법:
- 원래 선생님은 장애물을 전혀 모른다. 모방학습도 장애물 없는 에피소드로만 했다. 즉 회피는 가르친 적이 없고, 32 / 60 은 SAC 가 스스로 익힌 만큼이다.
- 충돌 평균 속도가 2.1~3.2 m/s 로 최저 속도(2 m/s)에 가깝다. 감속이 문제가 아니라 조향이 문제다. 그래서 브레이크는 효과가 없었다.
- 피하는 선생님을 모방해도 안 되는 건, 그 행동(장애물이 뒤로 갈 때까지 비켜 있기)이 지금 관측으로는 따라 할 수 없기 때문으로 보인다 (**추정**, 직접 검증 안 함).
- 학습 중 평가(고정 6장면)는 실력을 과대평가한다. 무충돌로 나온 모델도 장애물 배치를 바꾸면 절반 넘게 충돌했다.

## 7. 알려진 한계

1. **시야 91°**: 장애물이나 벽이 옆으로 오면 안 보인다. 차 앞 모서리는 카메라에서 0.25 m 안쪽이라 측정 범위 밖이다.
2. **기억 0.1 초**: 시야에서 사라진 것을 기억하지 못한다.
3. **표현력**: 읽기가 선형 한 층이고 DN 이 포화되면 더 세게 반응할 여지가 없다.
4. **고속 움직임 검출**: T4/T5 가 한 칸 간격만 잰다.
5. **센서 모델이 추정값**: 구멍·지연·pitch 오차·가짜 점은 실제 카메라로 맞춰야 한다.
6. **평가 장면이 적다**: 최고 모델 선택이 고정 6장면에 좌우된다.
