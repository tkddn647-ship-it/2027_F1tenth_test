# 맵 없이 LiDAR 만으로 달리는 강화학습 자율주행 (F1TENTH)

> LiDAR·IMU·속도만 보고, **지도·위치추정(SLAM) 없이** 40 Hz 로 조향·속도를 바로 내는 강화학습 정책.
> 시뮬레이터에서 학습해 팀 트랙 3바퀴 무사고 **9.63 초** (레이싱라인 이론값 10.0 초, Follow-the-Gap 12.7 초).

## 1. 문제

일반적인 F1TENTH 주행은 **지도 만들기(SLAM) → 위치추정 → 경로 추종** 순서다. 위치추정이 흔들리면 바로 사고가 나고,
지도가 없는 트랙에서는 달릴 수 없다. 목표는 **센서 입력에서 바로 행동**을 내는 정책: 실차에는 지도도, 레이싱라인도 없다.

## 2. 접근

```
LiDAR 최근 4스캔 (1125빔, 10 m)            ─ 1D CNN (프레임마다 같은 가중치) ─┐
IMU 요레이트·속도·직전 명령 (4구간 평균)   ─ FC ─────────────────────────────┴→ MLP → (조향, 속도 2~5 m/s)

학습할 때만: critic 이 레이싱라인 오차·곡률·목표 속도, 앞 장애물 위치를 추가로 봄 (asymmetric actor-critic)
```

- **Asymmetric actor-critic (SAC):** 실차에 올라가는 actor 는 센서만, 학습할 때만 쓰는 critic 은 "정답 정보"(레이싱라인)까지 본다.
  → 레이싱라인을 따라가는 빠른 운전을 배우지만, 실차에는 지도가 필요 없다.
- **시뮬레이터 직접 구현:** 단일 트랙 차량 모델(RK4), 서보·구동 지연, 브레이크 없는 타력 감속, 횡가속 한계, LiDAR 레이캐스팅·잡음·누락,
  IMU 100 Hz·속도 50 Hz, 계산 지연과 주기 흔들림, 랜덤 장애물. 실차 주기·센서 사양에 맞춤.
- **학습 맵 비율 설계:** 좁은 트랙(ifac·팀 트랙) 3 : 넓은 F1 서킷 축소판 1 — 넓은 트랙 위주로 학습했을 때 좁은 트랙을 잊는 문제(v2)를 보고 바꿈.
- **실차 배포:** 학습된 모델을 **torch 없이 numpy 로** 실행하는 ROS2 노드 (추론 1.1 ms/틱), 시작 시 LiDAR 방향 자동 검사,
  조종기 신호가 끊기면 정지하는 failsafe.

## 4. 부딪힌 문제와 해결

| 문제 | 원인 | 해결 |
|--|--|--|
| 학습 속도 5 steps/s (100만 스텝에 50시간) | LiDAR 를 2D 그림(BEV)으로 그리는 연산이 샘플당 4만 점 scatter | 극좌표 조회표(gather)로 바꾸고, 최종적으로 1D CNN 채널·stride 조정 → 연산 1/6, **35 steps/s** |
| 43만 스텝에 좁은 트랙을 전부 실패 | 학습 맵 4개 중 3개가 넓은 F1 서킷 → 넓은 트랙용 운전에 맞춰짐 | 맵 가중치 (좁은 3 : 넓은 1), 벽 여유 보상 추가 |
| 이어 학습 직후 정책 붕괴 (에피소드 837 → 114) | SB3 가 빈 버퍼를 **무작위 행동**으로 채움 | 이어 학습 땐 불러온 정책으로 버퍼 채우기 |
| 코랩이 끊길 때 모델 파일이 깨짐 (`BadZipFile`) | 저장 도중 끊기면 zip 이 반쯤 덮어써짐 | 임시 파일 저장 → 검증 → 교체 (원자적 저장), 깨진 파일은 건너뛰고 이어 학습 |
| 코너에서 횡가속이 늘 한계(6 m/s²)에 붙음 | 빠를수록 보상 → 한계까지 밀어붙임 | 횡가속 상한 4.5 m/s² + 한계 근처 벌점 (v4) |
| 실차 노드가 속도를 못 받음 | 토픽 타입 불일치 (Float64 vs Float32) | 실차 스택 코드 확인 후 맞춤 |

## 5. 한계와 다음

- 결과는 **시뮬레이션**이다. 서보 응답·타력 감속·코너 한계는 실측 전 추정값 → 실측 후 반영하고 재학습 예정.
- 팀 트랙 지도는 SLAM 지도라 실제 트랙 밖 바닥까지 빈칸으로 찍혀 있어, 9.63 초는 실제 트랙 폭보다 넓게 쓴 기록일 수 있다.
- 다음: 실차 저속(2 m/s) 시험 → 실측값 반영 → 실차 노드 C++ 이전(지연 감소).
